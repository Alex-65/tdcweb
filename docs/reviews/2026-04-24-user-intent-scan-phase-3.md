### (C) Phase-level lessons / pattern decisions

1. **Preemptive-polish pattern works.** Task 3.7 onwards eliminated b-task iterations when the polish pattern was known (i18n + text-error + empty state + null guards + localePath + focus-visible). Design-system reviewer flagged ZERO blocking findings on Task 3.7 vs ~3 findings on every prior UI task. Pattern should be documented in `docs/frontend/nuxt-playbook.md` for future list/detail pages in Phase 4+.

2. **Controller micro-edit threshold holds.** Controller-level direct edits (bypassing implementer dispatch) worked cleanly for 3 instances this phase -- all pure wrap / guard / class-list polish with no new logic. Threshold: change touches ≤3 lines AND adds zero new behavior OR wraps existing behavior. Anything more complex -> implementer dispatch.

3. **Plan internal contradictions surface under execution.** Two plan-internal contradictions caught during Phase 3: (i) Task 3.2 `<AppHeader />` unprefixed vs Task 3.3 `common/` subdir -> Nuxt 4 default naming conflict (Task 3.3 implementer added `components.pathPrefix: false`), (ii) Task 3.3 AppFooter `new Date()` in template vs CLAUDE.md SSR rule #4 -> year hoisted to script setup. Both closed by deviating from plan with explicit scan codification. Indicates future plan authoring should pre-check cross-task consistency.

4. **Design-system token gaps surface at first use.** `--color-error` token didn't exist until Task 3.6b needed it (list-page error surface). Then re-used by Task 3.7. Similar likely to happen in Phase 4+ (form-validation error, destructive CTAs). Phase 3 established the pattern: when a semantic token is missing, add to `@theme` + `:root` in the same task that needs it, don't defer. Alternative (wait for DESIGN.md / TD-007 consolidation) creates cascading blockers.

5. **i18n key expansion follows task boundaries cleanly.** Each task that added user-visible UI strings got paired plan amendment + 4-locale JSON amendment for that domain namespace (`home.*`, `home.seo.*`, `errors.*`, `locations.*`, `events.*`). Net: 9 new i18n keys across 4 locales = 36 translations authored during Phase 3 without overwhelming any single task.

6. **TDD discipline pays off.** Task 3.8 (useApi) was the only pure-TDD task of Phase 3. Test-first discipline caught the module resolution upfront; 4 tests authored before composable code; reviewer approved 0/0/0/2-low with ZERO rework. Pattern replicable for Phase 4 BFF server route handlers (`/api/auth/login.post.ts` etc.) which are plan-scheduled as TDD per §Phase 4.

7. **SSR discipline per CLAUDE.md rule #4 is not "nice-to-have".** Phase 3 caught the plan's attempted `new Date().getFullYear()` in AppFooter template + `new Date()` risks in event formatting. The rule forced early capture of browser-only APIs in script setup or composables with `import.meta.client` guards. Zero hydration warnings in Phase 3 dev boots is direct evidence of the discipline working.
